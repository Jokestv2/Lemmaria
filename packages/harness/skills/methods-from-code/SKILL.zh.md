# 依据实现撰写方法章节

按以下顺序，依据实现的真实行为撰写方法章节。

1. **先交代问题设定，再写方法。** 说明输入、输出，以及哪些量被固定。读者即使只读完这一段，
   也应当知道该方法用来做什么。
2. **描述流程，而非代码。** 写出读者复现所需的步骤。类名、文件名、函数名属于附录中的
   artifact 说明，绝不写进方法正文。
3. **每一个数值都要有出处。** 超参数、维度、阈值、学习率，只有在你确实读到取值时才写。
   没有读到，就写明"未指明"，不要选一个看起来合理的数字。
4. **区分"实际所做"与"可配置"。** 配置文件里的默认值是默认值，不等于本文的实验设置——
   要说明你报告的是哪一个。
5. **写明偏离之处。** 实现与所引方法不一致的地方要说出来。那通常正是贡献所在；若由读者
   自己发现，他对全文其余部分的信任也就没有了。
6. **按数据流经的顺序组织描述**，而不是按你恰好读到这些文件的顺序。

不要描述你没有读过的行为。方法章节里未经核实的句子，正是审稿人最先去查的那一句；一旦查出
是猜的，整篇论文的可信度都要为它付账。
